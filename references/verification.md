# 从导出文件验收到远程审阅

**剪辑台上的三遍。** 关闭旁白字幕看每章开头、中段、结尾，写下能从图本身读出的结论。再听声音闭眼理解论证，标记气口、轻声词、鼓点或提示音盖字的位置。最后按成片速度正常观看，并在所有换镜、字词入场和动作落点前后拖动。使用不同大小的播放器。评论给出的时间要先对应到同一版文件。

| 故障 | 分辨成因 | 验收 |
| --- | --- | --- |
| 声音似乎赶不上画面 | 在开头、中段、末段及反馈位置，对比 MP4 解码的人声与干声；与最终混音另作比对。检查固定偏移、逐渐漂移、局部事件错词三种形态 | 若原声对齐，再分别标出词起点、字达到可见阈值、下划线开始、场内高亮开始。示例成片中标签与线相隔 1–2 帧；阈值只服务于该设计 |
| 闪过一句无关文字 | 扫描每个普通标签的首次和末次可见帧。查词级门控与换镜是否打架、拖动后状态是否残留。数字计数器或用于演示长帧的短标记按语义单看 | 在最终 MP4 裁掉字幕，逐帧检查旧字消失到新词进入的区域；同时核对浏览器和导出 |
| 覆盖、黑线、内边距不足 | 测量实际字形、字重和变换后的边框，检查标签相交、目标外框、线段收起、临界帧、底部字幕带 | 全片按章节出联系表，尽量覆盖每种版式和转场中间帧。候选问题放大看实际像素。浏览器和离线渲染器各取同一帧比较；曾遇离线端使用 650 字重时出现大号字和缺字框，改用字体提供的字重后复核。横竖封面缩到手机列表尺寸另看 |
| 长段旁白只在「动」 | 对去字幕图像做滚动差分；同一视图超过 brief 中的时间或句数上限时，回到分镜找应该补的证据。字幕条不是可靠的句子边界；按原声合并或拆分 | 自动筛出的区段逐一处理；再人工检视即使像素变化也无解释进展的区段。推拉、光晕和背景循环都可能骗过像素检查 |
| 音乐抢词或音效突兀 | 分别听干声／音乐／混音。比较轻声片段、词头和鼓的瞬态，测波形时确保采样率、通道和起点相同 | 检查相位或相关峰位置而非只看单个相关系数；配乐会改变宽带波形。时间对了仍要听清词义。SRT 与烧录文本逐条核对 |

**长片导出。** 帧号统一到整数时间基，特效由绝对帧时驱动。可独立解码的分段要记源版本、起止帧、帧数和摘要；中断后复用验证过的段。改一场要覆盖它对两端转场的影响。合并前从各段取纯视频，再映射一条连续混音。逐段含 AAC 拼接可能带入编码预留样本，例如曾出现约 21 ms 的起点差。中间 MP4 若中断且没有 moov，单凭文件大小无法判断可用。用临时文件完成、探测、验证后替换正式件。

**交付。** 完整观看版、SRT、逐章起止／名称／介绍、可粘贴的视频简介和适合投稿入口的封面构成常规完整交付，具体以用户约定为准。工程需保存可编辑 Web 源、时间表、字体约定、声音授权、连续混音、必要的原始素材或已约定的取得方式。手机轻量版、干声、修改对照片段按需要提供。移动端能拖到近结尾并继续带声播放，才能算完整审阅片。抽查独立环境解压重建，避免绝对路径只在制作者机器上成立。

用户无法本地访问时，沿用已授权的远程位置、可见性和素材范围。有 GitHub 发布授权时，标记源码版本，先将视频和包上传到草稿 Release。核对分章、帧数、音画流、SRT、封面尺寸；比对本地／远端文件长度与 SHA-256，检查工程包成员和原始录制，最后发布并验证用户可用的直达链接。网络中断时先查远端资产状态，再续传缺件。确需分片时只暂存于授权范围内，拼回后校验整文件，清理临时片；以完整成片为首要入口。项目的投稿或外发权限需由当前任务决定。
